# 数据目录与隔离验证

## 路径优先级

1. 环境变量 `YANRUYU_DATA_DIR` 已定义：严格使用指定的独立绝对目录；非法路径报错，不回退到真实书库。
2. 源码模式（`app.isPackaged === false`）：使用程序根目录的 `.dev-data`；统一 `dev` 命令显式固定到工程 `.dev-data`，不随 staging 改变。
3. 便携发布模式：程序旁有 `data/` 时使用它；否则程序旁有历史 `portable` 标记时使用程序根目录。
4. 无便携标记的新发布：使用 Electron 的系统用户数据目录。

`data_paths.js` 只解析路径；`init_folder_setting.js` 建立所选目录。已有便携程序根目录的 `.reading-room` 完整保留。显式数据目录不做旧便携库路径重定位，不会从真实书库隐式复制内容。

## 目录内容

| 子路径 | 内容 |
| --- | --- |
| `database.sqlite`、`metadata.sqlite` | 本地书库与元数据；用户另外指定的元数据路径仍受原设置控制 |
| `setting.json`、`collectionList.json` | 配置与合集 |
| `.reading-room/` | Chromium 配置、旧 localStorage、窗口状态；userData 与 sessionData 同时指向这里 |
| `cover/` | 封面缓存 |
| `.cache/import-temp/` | 扫描/压缩包解压专用临时目录，可以被应用清空 |
| `viewer/` | 旧阅读器临时文件 |
| `reading-state.json`、`ui-state.json` | 两种界面共用的阅读档案及可恢复界面偏好 |
| `.data-protection/` | 恢复事务日志及自动恢复点 |
| `recovery/` | 压缩包删页前原包、恢复清单及撤回所需副本 |

历史的 `tmp/` 不再用于扫描清理；程序不迁移、删除该目录中的旧资料。任何源码备份、工作记录或其他用户文件都不应放进 `.cache/import-temp/` 或 `viewer/`。

## 显式隔离启动

```powershell
$env:YANRUYU_DATA_DIR = 'D:\Yanruyu-Development-Data'
npm run dev
Remove-Item Env:YANRUYU_DATA_DIR
```

变量只设置于当前终端及其子进程，不写系统环境变量。修改数据路径前先退出使用该数据目录的应用；不同目录的实例可以并存，同目录保留单实例锁。

`npm run test:desktop` 每次创建独立系统临时目录和四张中性几何图，使用真实 Electron、扫描、SQLite、阅读及管理界面往返，并重启验证隔离数据保留。它不会读取工程根目录的现有 `setting.json`、数据库、封面或浏览器配置，也不会结束其他正在运行的程序。

`npm run test:backup-desktop` 使用另一套独立目录和中性图片，经真实 preload IPC 验证备份导出、篡改包拒绝、预览、创建自动恢复点、恢复和重启后书目/进度/偏好还原。还会在测试实例退出后损坏当前 SQLite 和阅读 JSON，验证恢复界面仍能打开、好包可以修复数据、损坏原字节保存在完整原始恢复点。仅在该测试子进程内替换文件选择框与自动重启触发，防止产生未跟踪的新进程；实际备份、校验、SQLite 和恢复事务保持真实实现。

对新发布进行同样检查：

```powershell
node tools/test-isolated-desktop.cjs --package="E:\Exhentai Manage 3D\out\具体发布文件夹"
```

只允许测试工程 `out/` 内生成的发布目录。参数不接受当前程序目录。
