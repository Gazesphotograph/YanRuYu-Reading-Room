# 颜如玉 2.0 产品标准与迭代计划

2026-11-26 · 基于 Windows 桌面版 1.6.16，提交 `934d527`。本文是下一代的产品决策与拟定验收标准。测试结果列在末节。

## 一、产品决策

颜如玉面向两种经常发生在同一个人身上的需求：今天想接着看一本书，周末想把一批新书整理好。2.0 采用**同一窗口、同一书库、一套书籍详情与阅读器**。书库提供封面和表格两种视图。私人阅览室获得独立的一级入口与完整画布，专注于挑书、陈列和沉浸阅读。管理能力按任务进入书库、详情和设置。

这一决定有一个可验证的含义。用户在书库筛选某位作者，选中一本书，点击「在阅览室看」。房间打开同一批结果，镜头定位到该书。读完返回，仍能从原来的作者筛选、排序、滚动位置和选中书继续操作。全过程只产生一份阅读记录。

| 方案 | 用户得到什么 | 代价与判断 |
| --- | --- | --- |
| 仅保留 3D | 品牌鲜明，挑书有空间感 | 比较几十本书的作者、路径或缺失状态需要高密度表格。把这些操作放到场景中会增加查找和键盘操作的成本 |
| 仅保留管理界面 | 整理效率高，迁移范围较小 | 私人房间、真实封面陈列、布置和主题是现有独特资产。删除后，现有用户失去自己布置的空间 |
| 保留两个完整入口，或把旧管理页嵌入面板 | 短期开发量小，旧能力立即可用 | 仍要维护两套导航、焦点、设置与编辑反馈。现有经典页依赖保留的定制产物，嵌入也无法补齐其组件源码 |
| **共用应用框架，嵌入 3D 场景，按任务迁入管理能力** | 看书与整理各有合适的空间；同一本书从任一入口都可续读、编辑、找回 | **采用。** 主要成本是迁移经典页的独有行为。用逐项对照和兼容入口控制风险 |

## 三、窗口与核心流程

| 位置 | 首屏展示 | 主要操作与返回规则 |
| --- | --- | --- |
| **书桌** | 最近阅读的大封面、具体页码，接着是最近加入和自己的精选。空书库显示添加文件夹，第一次扫描显示首批可读结果与进度 | 一次激活续读。已导入但尚无阅读记录时，首屏展示最近加入。允许把书库或房间设为启动页 |
| **书库** | 左侧合集与智能书架，中间搜索结果，顶部为搜索、筛选和视图切换。封面卡片用于辨认作品，表格列出书名、作者、阅读状态和来源状态 | 单选打开右侧详情，多选出现批量工具条。进入「书库检查」处理缺失与重复，完成或取消后返回原列表与选择 |
| **阅览室** | 房间占满内容区。默认展示个人精选，书架边缘保留一个可收起的陈列选择器；从书库进入时明确标出当前合集或筛选 | 点击或键盘选书，显示书名、进度与「继续阅读」。可进入布置状态调光、换主题、摆书。在选中书上点「在书库显示」，直接定位到相应行 |
| **阅读器** | 正文占满窗口，按需唤出页码、缩略图和单页／双页／连续模式 | 进入时记住来源，退出时保存对应页、连续阅读偏移和焦点。保留外部阅读器入口。外部阅读器的页码能力在兼容清单中单独标明 |
| **全局工具** | 搜索和任务状态在主窗口位置固定；设置汇集数据目录、备份恢复、外观、快捷键与兼容选项 | 一个搜索入口支持书名、作者、标签和已导入的页内文本。命中某页可直达并返回同一组结果。扫描、导入、失败重试可在任务中心追踪 |

**界面取舍。** 当前 21:9 截图中，品牌标题、装饰文案、筛选工具和智能书架占据了书本上方的大块空间。2.0 把这片位置按任务分配：书桌给正在读的书，书库给第一行结果，房间给书架。房间保留八套主题的空间材质、陈列和光线偏好；表格、表单和错误提示使用稳定的实色底与可读文字。超宽屏用右侧详情支持左右对照；窄窗口把详情改为可返回的整页。现有示例见[空间截图](images/reading-room-21x9.png)与[平铺截图](images/library-grid-21x9.png)。

**第一个可操作原型只做三条流程。**

1. 首次打开 → 选择书库 → 首本可读时打开 → 切到双页 → 退出并重启 → 首页续读。用这条流程确定启动页、扫描反馈与阅读记录的边界。
2. 书库按作者筛选 → 选中一本 → 在阅览室看 → 读两页 → 返回原书架 → 在表格中编辑作者。若修改后书籍移出当前筛选，提示移出原因并提供「查看此书」，保留原查询。
3. 表格多选 → 发现两本疑似重复 → 并排查看封面、来源和进度 → 确认保留本 → 重启 → 撤销。取消比较应原样恢复多选。若发现来源离线，分别展示「重新定位」「移除记录」与各自影响。

## 四、2.0 应达到的标准

以下数字是规划门槛。第 1 周在指定设备复测 1.6.16，固定样本和计时方法，记录偏差后再锁定发布预算。

| 标准 | 拟定发布门槛 | 怎样验证 |
| --- | --- | --- |
| 续读准确 | 首页一次激活到上次阅读位置；单页、双页、连续阅读均恢复书籍、页与对应偏移 | 文件夹、ZIP/CBZ、7z 等受支持格式覆盖正常退出、立即关闭、重启和切换视图；按页和偏移断言 |
| 跨视图连续 | 书库、房间和阅读器往返无整页重载；当前合集、搜索、排序、选书与返回焦点可恢复 | 真实桌面脚本执行上述三条流程，检查状态与可见结果；删除、隐藏或筛除当前书另测 |
| 可信编辑 | 对用户宣告成功的修改可在重启后读回；普通编辑和批量操作遇到故障时各存储一致；扫描保留手选封面 | 在两个数据库写入之间、日志写入前后、磁盘只读及扫描并发时注入故障。比较书籍 ID、进度、收藏、合集和原文件哈希 |
| 大书库响应 | 建议目标为本地 SSD 上 1 万条目录冷启动到首屏可操作 P95 ≤ 3 秒，已建索引的目录搜索按键到结果 P95 ≤ 150 毫秒，热缓存本地图片翻页 P95 ≤ 150 毫秒 | 记录 CPU、GPU、内存、DPI、图像尺寸与缓存状态。启动至少测 30 次，交互至少 100 次；冷压缩包首次开书单列耗时与取消响应。3 万条数据做压力对照 |
| 房间流畅与降级 | 1080p、平衡档、参考集显上操作场景的帧时间 P95 ≤ 33 毫秒；静置 10 秒无主动增帧；关闭或丢失 WebGL 后仍可浏览与续读 | 记录 20 次翻架、阅读器往返、窗口最小化与恢复的帧时间和资源数量；验证同一选书可切回封面视图 |
| 可读与可操作 | 核心流程可只用键盘完成；文字、焦点和选中状态在浅深主题均清晰；减少动态效果时可直接选书 | 在 1280×720、2560×1080、150% 缩放及窄窗口检查。逐项验证焦点归还、屏幕阅读器名称及无需拖动即可完成的替代操作 |
| 升级可信 | 每份支持的历史样本升级后，逻辑书目、合并关系、阅读进度及偏好、合集、个人陈列和已导入文本可逐项核对 | 普通、便携、显式数据目录各走一遍，覆盖迁移中断、磁盘写入失败和书库离线。原始漫画逐文件哈希对比，恢复演练使用隔离副本 |
| 日常使用易学 | 建议招募 6 名试用者，兼顾以阅读为主和以整理为主的人；至少 5 人无需提示完成续读、切视图找回原书、批量预览与撤销各项任务 | 在同一台机器用中性书库观察任务完成率、用时和绕行步骤；原型和 Beta 各测一次。小样本用于发现障碍，不能推算总体使用率 |

## 五、工程迁移与工作顺序

**沿用已经验证的能力。** 保留 Electron、SQLite、稳定书籍 ID、现有扫描/解压服务、进度与备份格式的读取能力。房间以可挂载、暂停、释放的视图接入。阅读器和详情由共同入口管理。新界面复用现有服务，新增业务写入有单一主进程入口。

**选书状态由窗口统一持有。** 记录当前集合或查询、排序、选中 ID、滚动锚点、来源与返回位置。相机位置和家具布置由房间自己保存，表格列宽与密度由书库保存。业务数据使用稳定 ID；路径移动和封面变化触发局部更新。优先测量现有全库读取，再决定哪些查询分页或增量刷新。新导航和试验视图可用独立开关回退。

**经典管理页逐项接回。** 当前入口按本地标志动态导入房间或保留的压缩包，切换会重新加载页面。上游 Vue 目录可对照组件和术语，所有关键行为用当前发行版作为基准。建议用可构建的 Vue 组件承载新框架和管理表单，通过适配器接入现有原生 JS 场景与阅读器；第 2 周以垂直原型验证打包、加载和事件释放，再确定技术选型。[当前入口](../resources/app/dist/room-entry.js) · [来源与恢复边界](源码来源与恢复范围.md)

| 经典能力 | 2.0 归属 | 移交证据 |
| --- | --- | --- |
| 浏览、收藏、评级、标题与标签 | 书库和共享详情 | 从房间、书库分别编辑同一书目，刷新、重启后值一致 |
| 目录树、组合筛选、合集、批量编辑 | 书库侧栏、表格、批量工具条 | 用旧版保存的组合查询和合集对照成员；多选预览逐本列出变化，撤销可恢复 |
| 导入 SQLite 元数据、旧库导入、备份恢复 | 书库导入、设置中的数据管理 | 测试缺表、部分匹配、失败重试和跨目录恢复；结果逐类列出成功、跳过与失败 |
| 文件操作、第三方元数据来源、外部阅读器、托盘和高级设置 | 书籍操作菜单、来源设置、系统集成 | 逐项核对文件移动后的 ID、权限失败反馈、用户原配置、窗口与托盘行为 |
| 旧内置阅读器偏好、快捷键、主题 | 统一阅读器、快捷键与外观设置 | 建立旧选项到新行为的映射；有差异的项目在测试版保留兼容入口并写清使用方式 |

首发聚焦 Windows 本地阅读与收藏。安卓导出、跨设备续读、局域网共享扩展、新增房间主题、整库自动 OCR 留到后续版本评估。现有功能仍进入兼容清单，特别核对开启过旧选项的升级用户。

### 建议排期

按一名熟悉项目的全职开发者、可获得兼职设计评审和试用反馈估算 **12–16 周**。下表按 14 周安排。尚无真实设备性能基线和经典功能完整盘点，第 2 周与第 8 周各重估一次。

| 阶段 | 具体交付 | 通过条件 |
| --- | --- | --- |
| 第 1–2 周 · 基线与原型 | 建立旧功能与入口矩阵，标出当前用户数据、快捷键及替代入口；测两档 Windows 设备；以同一批示例书做三条可操作流程；为本次四个缺陷建立回归样本 | 评审者能亲手完成三条流程；确定首页、房间入口、键盘焦点和低配退路。每项关键旧能力都有迁移位置和负责人 |
| 第 3–4 周 · 数据与应用框架 | 修复下节列出的四项问题；接入统一导航、选书与返回状态；先贯通封面、表格、共用详情和现有阅读器 | SQLite 只读故障、日志容量边界、手选封面、未发现的单本刷新均有自动回归；从两种视图返回原书 |
| 第 5–6 周 · 房间与阅读 | 将现有 3D 场景作为独立全幅工作区接入；实现「在阅览室看／在书库显示」、精选陈列、低配回退与阅读器往返；重做书桌首屏 | 真实窗口内完成挑书、续读与返回，停帧、缓存预算和画质档位通过；可交付第一版内部 Alpha |
| 第 7–9 周 · 专业整理 | 交付高密度表格、属性面板、批量预览、重复对照、失联修复、导入和任务反馈；逐项迁入经典页独有操作 | 关键工作流可从新入口独立完成。并排对照旧版和新版的书目、进度与撤销结果；剩余差异有可访问的兼容入口 |
| 第 10–11 周 · 全面视觉与可用性收尾 | 对书桌、书库、房间、阅读器、系统对话框统一字体、色彩、焦点和反馈；覆盖窄屏、超宽屏、缩放与减少动态效果；完成第二轮任务观察 | 关键任务完成度达标；最常见的三类绕行已修正并复测。Beta 附能力对照、已知差异和回退说明 |
| 第 12–14 周 · 迁移与发布 | 用有历史数据的隔离副本验证升级、备份、恢复与重启；补齐低配性能及全量回归；干净 Windows 账户实测安装包；产出版本说明 | 数据完整性、关键功能、性能和升级验收全部有记录。缺陷影响进度或原件时阻断发布，次要兼容缺口明确延期并保留入口 |

**发布和回退。** Alpha 只用新目录与测试书库。Beta 在升级副本上记录版本与迁移步骤，保留可独立启动的 1.6.16 和经验证的升级前快照。回退界面沿用兼容的数据契约；若需要回退数据格式，原版使用升级前副本，并另存 Beta 期间的新数据，向用户明确恢复点时间。只有当旧能力矩阵逐项验收、关键任务脱离旧包运行后，才从主导航退役经典入口。

## 六、本轮审查发现与验证

| 优先级 | 已查明的行为 | 修复与回归 |
| --- | --- | --- |
| P1 · 普通编辑只写入一半 | 保存先更新主书库，再更新元数据库。对临时 SQLite 的元数据库启用只读后，保存报错，但主书库收藏已为真、元数据库仍为假。[普通保存](../resources/app/index.js) | 复用项目 SQLite 导入已有的附加数据库事务方式，或使用可恢复日志。覆盖第二次写失败、重试和重启读取 |
| P1 · 大型整理历史可能阻断下次启动 | 容量预检使用紧凑 JSON，实际写盘使用带缩进 JSON，启动按文件字节限制 64 MiB。构造的 180 组合法批量变更通过格式验证，紧凑值 22.17 MiB，实际序列化 64.07 MiB。该数字来自序列化实验，未在真实用户库执行批处理。[容量检查](../resources/app/modules/library_organizer.js) · [写盘实现](../resources/app/modules/reading_state.js) | 对同一份序列化字节检查并写入；为已超限的合法旧日志设计受控恢复。回归覆盖边界前后、应用后重启及备份恢复 |
| P2 · 编辑过的封面在扫描后消失 | 临时书目设置自选封面后改动一页，增量扫描重新生成封面，并删除书库中原有的自选封面副本。用户最初选择的源图片与这份受管理副本是两个文件。[扫描提交与清理](../resources/app/modules/library_scan.js) | 分开记录自动封面和用户覆盖。回归覆盖增量扫描、移动、重建、备份还原；为老记录制定保守的封面保留策略 |
| P2 · 单本刷新会将未处理报告为成功 | 请求中的书籍 ID 有数据库记录，但扫描发现列表中没有该路径时，返回处理 0、失败 0。单本入口随后读回旧记录，调用方收到原页数与封面。[扫描筛选](../resources/app/modules/library_scan.js) · [单本刷新入口](../resources/app/index.js) | 按请求的书籍 ID 返回实际结果，区分已刷新、被排除、缺失和暂不可访问；界面允许重新定位或调整规则 |

## 九、第三轮预览 · 整理历史与恢复 · 2026-11-26
