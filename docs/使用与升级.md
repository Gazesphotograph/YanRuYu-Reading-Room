# 颜如玉：使用与升级

双击 `exhentai-manga-manager.exe` 启动。新构建的发布文件夹不包含任何私人书库、登录设置、封面、阅读进度或浏览器资料，也不需要 Node.js。

## 首次运行

全新发布默认把数据放在系统用户应用数据目录。也可在程序旁自行新建 `data` 文件夹使用便携模式，或在启动终端设置 `YANRUYU_DATA_DIR` 为独立数据目录的绝对路径。

## 升级现有便携版

1. 在应用中创建并验证包含数据库、设置及阅读状态的备份，退出使用该数据目录的应用。
2. 保留现有数据位置。新发布解压到新的程序目录，不要把整个旧目录删除或覆盖。
3. 从当前终端设置 `YANRUYU_DATA_DIR` 指向原数据目录，再启动新程序；检查书库、收藏、阅读进度和设置。现有数据目录中的原程序文件可以继续保留用于回退。
4. 确认后更新自己使用的快捷方式。原程序和备份在验证完成前保留。

若继续使用原便携目录，应仅替换程序文件与 `resources/` 下的应用资源。不要删除或覆盖 `database.sqlite`、`metadata.sqlite`、`setting.json`、`collectionList.json`、阅读状态文件、`cover/`、`.reading-room/`、备份目录或漫画源文件；不要让解压软件删除包中没有的数据文件。独立数据目录更便于后续升级。

现有 `portable` 标记仍兼容；如果原程序数据与程序混放，不设置环境变量而只启动另一个无标记的新目录，会得到空书库，这是数据路径不同，不代表旧数据丢失。

## 需要保留的资料

书库与元数据数据库、配置与合集、阅读状态文件和 `.reading-room`、封面及备份都属于用户数据。漫画正文仍在配置指定的书库目录。`.cache/import-temp/` 和 `viewer/` 是程序专用临时目录；原 `tmp/` 不再自动清空。

第二阶段的智能书架、筛选位置和画质随 `ui-state.json` 备份，每本书的阅读模式、方向、缩放等偏好随 `reading-state.json` 备份。`task-state.json` 只保存任务历史与重试信息，不包含在完整备份中，也不进入发布包；丢失它不影响书目、收藏和阅读档案。

第三阶段的整理与撤销日志在 `library-organizer.json`；别名与确认导入的文本在 `local-search.json`；房间布置、精选顺序和声音偏好随 `ui-state.json` 保存。这些均属于私人资料，完整备份包含它们。恢复到另一个数据目录后，整理记录仍能撤销；恢复较老、不含这些文件的备份时，会清空新版功能的对应状态，避免把旧撤销日志应用到另一份书库。

`viewer/` 现在保存受容量预算约束的解压缓存。可以在阅览室设置中调整上限或清理空闲缓存；正在阅读的缓存会保留到关闭阅读器。预算默认 2 GB，首次打开较大压缩包时可能需要提高容量。

发布脚本每次只创建新的程序文件夹，不自动安装、覆盖旧程序、迁移真实数据或发布到网络。

## 整理缺失书目

在「书库整理 → 缺失文件」点击「检查书库」，可以逐本删除、勾选多本后删除，或一键选择删除全部缺失及暂不可访问记录。核对删除清单后确认；想保留记录时可取消，或使用「重新定位原书」。

删除只移除书库中的记录，原文件、封面、元数据、阅读档案和合集引用保留。可在「整理历史」选择「恢复删除的书库记录」，重启程序或恢复完整备份后也能撤销。提交前会再次检查路径；如果书籍恢复访问或记录已被修改，会停止这批删除并提示重新检查。

## 换电脑或移动书库

保留书库数据库、阅读状态和整理日志，在新电脑选择漫画所在的新文件夹并完成一次扫描。旧路径已不存在、完整内容指纹一致且匹配唯一时，程序沿用原书籍编号并更新路径，阅读进度、阅读偏好、收藏和自定义书名随原记录保留。旧路径仍存在的相同内容副本保持独立。

迁移前建议在旧电脑完成一次扫描，让早期书目补齐完整内容指纹。没有历史完整指纹的失联记录，或存在多个无法区分的旧记录时，不会仅凭书名、页数或封面自动合并。读取书单也不会再按同名文件夹猜测并改写旧路径。

若旧版本已产生重复，进入「书库整理 → 疑似重复」，选择对应的一组，再展开「合并所选书籍的书架展示」。保留本选择当前路径可以打开的那条，阅读进度来源选择原来读过的记录；只有一条有进度时会自动选中它。若两条都指向当前可用路径，可直接保留原来读过的记录，同时保留它的阅读偏好。预览现在会区分显示书名、书名和真实文件夹名。

旧来源离线时，只有保存过完整指纹且与当前保留本实测内容一致，才能参与合并。合并保留所有来源记录和阅读档案，可从整理历史撤销；后续扫描会识别这次合并，隐藏来源改名或搬迁也会继续保留隐藏状态。

## 减少程序占用空间

新版发布保留中文简体、中文繁体及英文本地化资源，并去掉生产依赖中的测试、文档和类型声明。原生数据库、图片处理模块、阅读器、图形回退及许可证均保留。

程序可在 NTFS 分区使用 Windows 自带的 LZX 无损文件压缩，直接双击 EXE 运行。文件内容与校验值不变，资源管理器的“大小”仍是原大小，“占用空间”会减少。它不减少程序运行时所需内存，也不保证启动一定更快。

ZIP 解压或换盘复制后，文件压缩属性可能不保留。可在新程序目录运行附带的 `优化程序磁盘占用.ps1` 再次压缩；不执行此脚本也能正常使用程序。非 NTFS 分区按普通文件运行。
