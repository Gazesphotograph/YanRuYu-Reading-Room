## 恢复程度

| 部分 | 当前权威来源 | 状态 |
| --- | --- | --- |
| Electron 主进程、数据库、文件读取与安全逻辑 | `resources/app/` 中的原生 JavaScript | 现有定制源码完整保留，可直接维护、构建及运行 |
| 3D 阅览室、主题、玻璃效果、阅读器与新增保护界面 | `resources/app/dist/` 中未压缩的 JS/CSS | 直接运行的源码完整保留；文件夹名 dist 不代表这些文件是丢失源码的构建产物 |
| 完整管理页 Vue 组件 | 上游同版本 `src/*.vue` | 已恢复可编译的参考入口，但不是定制版本的等价来源 |

| 7-Zip 与外部阅读器 | `resources/extraResources/` | 保留现有二进制及已有许可证；未声称已从对应源码重编译这些工具 |

已知管理页本地差异包括品牌/窗口交互、8 主题、移除旧关于页、IPC 适配、第一阶段身份进度桥接和导入结果处理。恢复的上游 Vue 不自动带入这些变化。发布流程只从当前 `resources/app` 构建，绝不以下载到的上游源码替换本地版本。

第一阶段对现有管理页的读档桥接与导入反馈修补分别保留在 `tools/patch-classic-reading-state.cjs` 和 `tools/patch-classic-import.cjs`，便于复核这些新增修改。更早的主题、品牌等定制仍以保存的管理页产物和独立增强模块为依据；这两份补丁不是整套 Vue 定制的替代来源。

## 构建边界与后续迁移

`npm run build` 拷贝允许的当前源码并在新 staging 安装锁定生产依赖。原生前端 JS 无需转译，`build-manifest.json` 对每个应用源文件保存 SHA-256。`npm run package` 从锁定 Electron 44.3.0 发行运行时组装 Windows x64 文件夹，并核对这些哈希。

打包时使用锁定的 rcedit 5.0.2 将现有 `public/icon.ico` 写入新可执行文件，保留原 E·H 图标；只允许编辑 `.build/` 或 `out/` 中的新文件。发布清单另外记录处理后可执行文件的 SHA-256，审计时一并核对。现用程序文件不被修改。

`npm run manager:reference` 单独安装参考依赖并编译 Vue 到新的 `.build/manager-upstream-reference-*` 目录，用于对照、逐个迁移组件。它不参与 `build` 或 `package`。在替换管理页之前，需要把全部本地行为迁入 Vue、重新测试管理页主题/读档/导入/窗口功能，并更新 `room-entry.js` 的真实产物入口。第一阶段尚未完成这一 Vue 迁移，当前生产功能以保留的定制产物为准。

原上游设置页导入未提交的 `secret_key.json`。参考构建只在隔离 staging 自动写入空的 `gh_token`，不读取、查找或复制任何私人密钥。参考工程的旧依赖按原锁固定，仅用于恢复对照；不加入当前生产包。

## 可审计发布

Git 和发布都使用允许列表，生产依赖只从 `resources/app/package-lock.json` 在新 staging 安装，不复制现用程序的 node_modules。发布清单只包含相对文件名与哈希，来源说明不包含本机登录信息。输出独立存放在 `out/`，不会覆盖任何现有程序或数据。
